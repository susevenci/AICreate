# M7 演进说明

> 本文件记录 M7 的触发条件、已落地项与尚未启动项的评估结论。M7 默认不改变现有架构，只做查询层优化与演进预案。

## 1. 触发条件

满足以下**任两条**才启动结构性演进：

1. vault 笔记数 > 5000，首页首屏 > 3 秒
2. 需要多人协作或移动端深度编辑
3. 需要复杂交互（拖拽看板、实时协同、富媒体预览）
4. 需要对外提供 SaaS 形态

未达标时，继续沿用当前「零依赖 Node + Markdown」形态。

## 2. 已落地：查询缓存

- `app/lib/vault.mjs` 的 `listByType` 增加 60 秒内存缓存，键为类型名。
- 所有写操作（`createNote` / `updateFields` / `updateConfig` / `trashNote`）调用 `invalidateCache()`，保证读后写立即可见。
- 断言覆盖：`listByType 命中缓存`（两次调用返回同一引用）、`写操作后缓存失效`（新建后数量增加）。
- 代价：单进程内缓存，多实例部署时不适用；当前是单用户本地服务，可接受。

## 3. 候选演进 A：Obsidian Bases

- 适用：Dataview 查询变慢、或需要更接近表格软件的操作体验。
- 边界：Bases 与 Dataview 双写会造成字段漂移，**只能整体替换，不能并存**。
- 迁移顺序：先替换只读页（首页/收支/作品），再替换带交互的页（选题池/计划）。
- 回滚：保留 Dataview 页面文件，改回入口链接即可。

## 4. 候选演进 B：AI 流式桥接

- 现状：AI 型 Skill 只渲染 prompt，由外部 Agent 执行，产物落 `01-收件箱/_ai-output/`。
- 演进：本地服务直连模型并 SSE 推流，需新增 provider 配置（密钥只进 `.env.local`）。
- 风险：密钥与费用由用户承担；必须保留「只生成 prompt」的降级路径。
- 前置：先有稳定的 provider 抽象与用量统计，再谈流式。

## 5. 候选演进 C：只读镜像 Web 化

- 现状：页面由服务端渲染，交互靠原生 JS，无构建链。
- 演进：仅当需要拖拽看板、实时协同等客户端复杂状态时，才引入框架。
- 边界：数据层不动，Web 只做镜像与 API 回写，避免双状态。

## 6. 决策记录

任何一项启动前，必须在 `vault/00-工作台/_配置.md` 的「变更记录」写入：

```
- YYYY-MM-DD | 演进 | 启动 {A/B/C}：触发指标=…，回滚方式=…
```

未写决策记录不得动工。
