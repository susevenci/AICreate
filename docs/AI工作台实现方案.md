# AI 内容工作台 — 实现方案 v3

> 依据：《AI内容工作台分享》正文（含"搭建前准备"）、12 张官方界面截图、网页全文采集结果
> 产出性质：设计文档，不含完整代码；关键查询与契约给出可直接使用的骨架。

---

## 零、版本变更说明

| 版本 | 技术底座假设 | 结论 |
|------|--------------|------|
| v1 | 自研本地 Web 应用（Next.js） | 过度设计 |
| v2 | 双宿主同构（Web 为主 + Obsidian 兼容） | 方向正确，但主次颠倒 |
| **v3** | **Obsidian + Dataview + Codex + Skill + Excalidraw** | **与原版一致，可落地** |

v3 的依据是正文"一、搭建前准备"给出的五件套：

- **Obsidian**：保存定位、产品、素材、文案和复盘
- **Codex**：读取资料并执行任务
- **Skill**：保存已经跑顺的方法
- **Dataview**：显示可视化工作台
- **Excalidraw**：需要可编辑画板时再配置

关键推论：**工作台页面不是写出来的，是查出来的**。所有页面本质是一篇 Obsidian 笔记 + Dataview/DataviewJS 查询，数据存在 frontmatter 里。这解释了截图中的"刷新本页"（Dataview 需要手动刷新视图）和"打开完整表格"（跳转到另一个 Dataview 笔记）。

因此整份方案的重心从"写前端"转为**设计字段、写查询、定契约**。

## 一、需求还原

### 1.1 主线流程

原文明确：

```
热点与素材 → 选题 → 拆解 → 创作 → 标题封面 → 发布检查 → 数据复盘
```

闭环回到热点与素材，沉淀物进入资产库。

### 1.2 十模块职责

| # | 模块 | 一句话职责 | 关键产物 |
|---|------|-----------|----------|
| 1 | 首页 | 打开就知道从哪继续 | 待办视图、当前稿件指针 |
| 2 | 对标与热点 | 发现值得研究的内容 | 博主、作品快照、异常值 |
| 3 | 选题 | 把不同来源的想法放到一起 | 选题卡（问题+材料+角度） |
| 4 | 拆解与沉淀 | 先读懂原文，再留下有用做法 | 拆解结论、四类资产 |
| 5 | 创作 | 围绕当前稿件继续推进 | 稿件、标题、封面 brief |
| 6 | 发布与经营 | 发布后继续补数据 | 作品、指标、复盘结论 |
| 7 | 计划 | 把目标变成具体任务 | 任务、日程 |
| 8 | 常用助手 | 按场景调用 Skill | 运行记录、产物 |
| 9 | 画板 | 直接整理可视化内容 | Excalidraw 画板 |
| 10 | 收支 | 记录现金流（截图补，正文未写） | 收支流水 |

### 1.3 四条搭建原则 → 工程约束

| 原文原则 | 工程约束 | 验收方式 |
|----------|----------|----------|
| 先解决一个最重复的任务，不要一开始追求大而全 | 每期只做一条链路，页面数不增加 | 每期结束有一个真实可用的端到端场景 |
| 先想清楚输入、动作、结果和下一步，再做界面 | 先定 frontmatter 与输出模板，再写查询 | 每个页面先有字段，再有视图 |
| 知识库保存资料与结果，Skill 保存处理步骤，工作台负责找资料和发起任务 | 三层物理分离：`02/03/04/08` 存结果、`.codex/skills` 存步骤、`00-工作台` 只做视图 | 视图层不存业务数据 |
| 每加一个功能都实际做一次：资料读对、任务传对、结果存对、重开还能找到 | 四段验收固化进每期清单 | 关闭 Obsidian 重开后复验 |

### 1.4 交付边界

- **免费版范围**（原文口径）：首页、常用笔记、当前稿件、一个任务入口。
- **完整版增量**：10 套 Skill、1 套选题库、1 套对标博主拆解库、3 套爆文拆解库、完整拆解规则与配置。
- **外部依赖**：数据源与转写服务由用户自备账号，系统必须可降级为手工录入。各字段的具体来源、采集等级与分平台路径见第八章。

### 1.5 截图补充的产品事实

1. 顶部全局搜索：`搜索选题、文案和资料...`
2. 导航 10 项带图标，当前项高亮
3. 首页：时钟 + 日历（月/周/日/列表）+ 本月经营结果 + 作品与机会（随手记录、作品封面墙）+「编辑布局」
4. 对标页：4 张计数卡 + `查看获取详情` + `恢复自动更新 / 更新动态 / 添加博主`
5. 拆解页：1-2-3 步横条 + 素材来源二选一（粘贴文案 / 从视频提取）+ 输入接受"文案、飞书行、链接或文件路径"
6. 资产页：4 库 57 条，角度库三列（角度名称 / 适合解决什么内容问题 / 用户为什么会关心），每行可跳原笔记
7. 创作页：6 步 Tab（聊思路 / 写文案 / 起标题 / 做封面 / 发布检查 / 发布），做封面下挂两个封面 Skill
8. 发布页：月份选择 + 4 Tab（经营总览 / 作品画册 / 内容复盘 / 导入数据）+ 口径与缺口提示
9. 计划页：今日安排 + 待安排未完成（优先级、原计划日期、改期）+ 周日历
10. 助手页：我的常用 / 全部助手，按阶段分组的卡片，右上角收藏
11. 画板页：新建 + 历史缩略图墙 + 搜索 + 逐张删除

## 二、产品定位与设计原则

**定位：用 Obsidian 当一个可查询的数据库，用 Dataview 当报表，用 Codex 当执行同事，用 Skill 固化方法。**

七条设计原则：

1. **视图不存数据**：`00-工作台` 下的笔记只放查询与说明，业务数据一律在各自目录。
2. **一对象一文件**：选题、稿件、作品、任务、资产、流水都是独立笔记，文件名即标识。
3. **字段即接口**：frontmatter 是唯一契约，字段改动等于接口变更，必须同步模板与 Skill。
4. **值可中文，键必须英文**：避免 Dataview 属性名歧义，中文只出现在值里。
5. **单入口**：一天从首页开始，首页必须回答"现在做什么"。
6. **人在环上**：AI 只产出到暂存区，入库、发计划、登记发布均需人工确认。
7. **口径透明**：统计必须写明计算口径与数据更新时间，脏数据显式提示条数。

## 三、整体架构

### 3.1 方案对比与决策

| 方案 | 实现 | 落地成本 | 交互上限 | 结论 |
|------|------|----------|----------|------|
| A. Obsidian 原生栈 | Dataview/DVJS 渲染页面，Codex 执行 | 低（无构建、无部署） | 中（受 DOM 与刷新机制限制） | **采用** |
| B. 自研 Web 应用 | Next.js + 文件系统 API | 高（前后端 + 打包 + 升级） | 高 | 保留为 M7 可选演进 |
| C. 混合 | Obsidian 管数据，Web 只读镜像 | 中 | 高 | 不推荐（两套状态易漂移） |

决策理由：原方案的竞争力在**方法与资产**，不在前端工程。用 A 可以在两周内交付可用产品，且数据天然可迁移。只有当单库笔记超过约 5000 篇、DVJS 渲染明显卡顿时，才需要 B。

### 3.2 四层架构

```
┌───────────────────────────────────────────────────────┐
│ 视图层  00-工作台/  (10 个页面笔记 + DVJS 组件库)       │
│         只读查询 · 按钮只做跳转/生成指令                │
├───────────────────────────────────────────────────────┤
│ 执行层  Codex CLI  +  AGENTS.md  +  .codex/skills/      │
│         读文件 → 处理 → 按模板回写 → 返回摘要           │
├───────────────────────────────────────────────────────┤
│ 资产层  02-知识库 / 03-对标 / 04-选题 / 05-拆解 /       │
│         06-资产 / 07-稿件 / 08-作品 / 09-计划 / 10-收支 │
├───────────────────────────────────────────────────────┤
│ 数据层  Markdown + frontmatter + wikilink（Obsidian vault）│
│         可选：Excalidraw / Canvas / 附件                 │
└───────────────────────────────────────────────────────┘
```

补充能力层：`_snippets/` 放 CSS（卡片、配色、暗色主题），`12-模板/` 放 Templater 模板。

### 3.3 数据流

```
Codex 抓/整理 ──→ 03-对标 ──┐
用户粘评论/课程 ─────────────┼→ 04-选题 ──→ 05-拆解 ──→ 06-资产
                            │                              │
                            └──→ 07-稿件 ←────────────────┘
                                    │
                                    ↓
                                08-作品 ──→ 指标笔记 ──→ 复盘
                                    │                      │
                                    └──────→ 10-收支 ←─────┘
```

### 3.4 宿主与工具版本

- Obsidian 1.13.x（启用 Dataview、Templater、Excalidraw、QuickAdd、Calendar 可选）
- Codex CLI（或任意可执行本地任务的 Agent CLI，通过 `AGENTS.md` 适配）
- Node 22+（仅用于批量脚本：CSV 导入、索引检查）


### 4.2 命名与标识

- 文件名格式：`类型-标题-YYYYMMDD.md`，例：`选题-为什么你的封面没人点-20261022.md`。
- 不依赖 frontmatter 里的 `id` 做关联，一律用 `[[wikilink]]`，改标题时靠 Obsidian 自动更新链接。
- 附件命名：`作品-标题-封面.png`，与作品同名，便于 DVJS 匹配。

### 4.3 实体定义

字段分三类：**必填**（写入即校验）、**选填**、**派生**（由查询计算，不落盘）。

#### 4.3.1 选题 topic（`04-选题/`）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 是 | 固定 `topic` |
| status | string | 是 | `backlog`/`researching`/`selected`/`in-production`/`archived` |
| origin | list | 是 | 来源：`course`/`comment`/`published`/`note`/`thought`/`benchmark` |
| refs | list | 否 | 来源链接 `[[...]]` |
| problem | string | 是 | 观众遇到什么问题 |
| material | string | 是 | 我有什么材料可讲 |
| angle | string | 否 | 切入角度 |
| fit | number | 否 | 1-5 适配度（人工或 AI 建议） |
| createdAt | date | 是 | 创建日期 |

```yaml
---
type: topic
status: selected
origin: [comment, benchmark]
refs: ["[[作品-某爆款-20261020]]"]
problem: 封面做了但没人点，不知道问题出在哪
material: 自己 3 个月 40 篇封面的点击率对比数据
angle: 用对比找到真正差异
fit: 4
createdAt: 2026-10-22
---
```

状态机：`backlog → researching → selected → in-production → archived`。进入 `selected` 的前置条件：`problem` 与 `material` 均非空。

#### 4.3.2 对标博主 blogger（`03-对标/博主/`）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 是 | `blogger` |
| platform | string | 是 | 平台名 |
| followers | number | 是 | 粉丝数 |
| profileUrl | string | 否 | 主页 |
| baseline | number | 否 | 互动基线（近 20 条中位数，脚本或人工填） |
| fit | string | 否 | `适合我`/`不适合`/`待观察` |
| fitReason | string | 否 | 判断理由，`fit` 非空时必填 |

#### 4.3.3 对标作品 source（`03-对标/作品/`）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 是 | `source` |
| blogger | link | 是 | `[[博主-xxx]]` |
| platform | string | 是 | 平台 |
| publishedAt | date | 是 | 发布日期 |
| views | number | 否 | 播放/阅读 |
| likes / comments / shares | number | 否 | 互动 |
| engagement | number | 派生 | (likes+comments+shares)/views |
| flags | list | 派生/选填 | `lowfan-viral`/`outlier`/`recent3d` |
| rawPath | string | 否 | 正文文件路径或链接 |
| body | text | 否 | 正文（也可放 `_attachments` 或独立 md） |
| source | string | 是 | 采集等级：`manual`/`csv`/`api`/`agent` |
| fetchedAt | date | 否 | 采集时间，用于判断数据新鲜度 |

`flags` 由查询计算或脚本打标：低粉爆款 = `博主粉丝 < 阈值 && engagement > 阈值`；异常值 = `views > baseline * 2`。

#### 4.3.4 拆解 analysis（`05-拆解/`）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 是 | `analysis` |
| stage | string | 是 | `intake`/`verify`/`result`（对应界面 1-2-3 步） |
| sources | list | 是 | 被拆解作品 `[[...]]` |
| highlights | list | 否 | 亮点 |
| weaknesses | list | 否 | 不足 |
| borrowable | list | 否 | 可借鉴做法 |
| patterns | list | 否 | 横向共同规律 |
| assets | list | 否 | 沉淀出的资产 `[[...]]` |
| runId | string | 否 | 对应 `.codex/runs/` 记录 |

正文用固定四段结构：`## 单篇结论` / `## 横向比较` / `## 可借鉴做法` / `## 原文摘录`。摘录每条带来源锚点，便于溯源。

#### 4.3.5 资产 asset（`06-资产/`）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 是 | `asset` |
| assetType | string | 是 | `angle`/`structure`/`opening`/`title` |
| name | string | 是 | 资产名 |
| problem | string | 是 | 适合解决什么内容问题 |
| why | string | 是 | 用户为什么会关心 |
| skeleton | text | 否 | 结构/模板正文（structure、title 用） |
| usedIn | list | 派生 | 被哪些稿件引用（查询 `07-稿件` 反链） |
| source | link | 否 | 来源拆解 `[[...]]` |

四库字段差异：

| 库 | 专属字段 |
|----|---------|
| 选题角度 | `problem`、`why` |
| 文案结构 | `skeleton`（段落骨架）、`applicable`（适用内容类型） |
| 开场白 | `example`（原文示例）、`scene`（适用场景） |
| 标题 | `template`（模板）、`slots`（变量槽位）、`platform` |

#### 4.3.6 稿件 draft（`07-稿件/`）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 是 | `draft` |
| status | string | 是 | `active`/`done`/`dropped` |
| step | string | 是 | `idea`/`copy`/`title`/`cover`/`checklist`/`publish` |
| topic | link | 否 | `[[选题-...]]` |
| audience | string | 是 | 这篇解决谁的什么问题 |
| platforms | list | 否 | 目标平台 |
| assets | list | 否 | 引用的资产 `[[...]]` |
| titles | list | 否 | 候选标题 |
| cover | link | 否 | 封面图或 brief 笔记 |
| version | number | 是 | 定稿递增 |
| recordCard | link | 否 | 录制卡片 → 画板 |

正文结构固定：`## 思路` / `## 正文` / `## 标题候选` / `## 封面 brief` / `## 发布检查`。

#### 4.3.7 作品 work（`08-作品/作品/`）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 是 | `work` |
| draft | link | 是 | 原稿 `[[...]]` |
| publishDate | date | 是 | 发布日期 |
| cover | link | 否 | 封面 |
| platforms | list | 是 | 发布平台（多平台也只记一条作品） |
| urls | list | 否 | 各平台链接 |
| topic | link | 否 | 来源选题（用于来源效果对比） |

#### 4.3.8 指标 metric（`08-作品/指标/`）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 是 | `metric` |
| work | link | 是 | `[[作品-...]]` |
| date | date | 是 | 数据日期（缺失则不计入月度统计） |
| platform | string | 否 | 分平台记录 |
| views | number | 否 | 播放/阅读 |
| inquiries | number | 否 | 咨询 |
| deals | number | 否 | 成交 |
| source | string | 是 | `manual`/`csv`/`api` |

**口径铁律**：views、inquiries、deals 三个字段互不推导；月度成交按**记录数**统计，不去重，不去推算。

#### 4.3.9 任务 task（`09-计划/任务/`）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 是 | `task` |
| status | string | 是 | `todo`/`doing`/`done`/`unscheduled` |
| date | date | 否 | 计划日期（空即"待安排"） |
| priority | string | 是 | `high`/`normal`/`low` |
| estimate | number | 否 | 预估分钟 |
| originDate | date | 否 | 原计划日期（用于"改期"追溯） |
| ref | link | 否 | 关联稿件/选题/作品 |
| source | string | 是 | `manual`/`ai` |

#### 4.3.10 收支 ledger（`10-收支/`）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 是 | `ledger` |
| kind | string | 是 | `income`/`expense` |
| amount | number | 是 | 金额（正数，方向由 kind 决定） |
| date | date | 是 | 发生日期 |
| category | string | 是 | 课程/带货/投放/订阅/其他 |
| work | link | 否 | 关联作品（内容带来的收入） |

#### 4.3.11 收件箱 inbox（`01-收件箱/`）

## 五、视图层设计（Dataview）

### 5.1 渲染策略

| 场景 | 技术 | 理由 |
|------|------|------|
| 纯表格（资产、流水、指标） | DQL `TABLE` | 快、稳定、可排序 |
| 列表（待办、近期稿件） | DQL `LIST`/`TASK` | 轻量 |
| 卡片、统计块、进度、日历 | DataviewJS | 需要 DOM 与聚合 |
| 按钮、跳转 | DVJS + `app` API | 无插件依赖 |

约定：
- 每个页面笔记顶部固定一段"导航条"，10 个页面互链，当前页用粗体标记（或用 DVJS 统一渲染 tab 栏，保证样式一致）。
- 所有 DVJS 必须包 `try/catch`，异常时渲染空态提示而不是白屏。
- 所有查询必须带 `FROM` 限定目录，禁止全库扫描。

### 5.2 通用组件（放在 `00-工作台/_配置.md` 或独立 `_组件` 笔记，用 DVJS 引入）

1. **`statCard(label, value, caveat?)`**：统计卡，必须支持 `caveat` 参数渲染口径说明（对应截图"按成交日期·记录数，不去重"）。
2. **`emptyState(text, createLink)`**：空态卡片，附"新建"链接。
3. **`refreshButton()`**：执行 `dataview:dataview-force-refresh-views`，对应截图"刷新本页"。
4. **`sectionTitle(title, count)`**：区块标题带条数。
5. **`linkButton(label, targetNote)`**：跳转按钮。
6. **`qualityWarning(items)`**：数据质量条，列出缺失条数与定位链接。

## 六、执行层：Agent 与 Skill

### 6.1 AGENTS.md 执行契约（`/.codex/AGENTS.md`）

必须写清的六件事：

1. **目录职责**：每个目录放什么，哪些目录禁止写入。
2. **字段规范**：所有 frontmatter 字段名、类型、枚举值。
3. **输出格式**：每种产物的固定 Markdown 结构（标题层级与区块顺序）。
4. **落盘规则**：先写暂存区 `01-收件箱/_ai-output/`，人工确认后再移动到正式目录。
5. **命名规则**：`类型-标题-YYYYMMDD.md`，标题取自身内容，禁止拼音。
6. **禁止动作**：不得删除文件、不得改写 `00-工作台`、不得跨目录移动用户文件、不得编造数据。

### 6.2 Skill 目录格式

Skill 分两级来源，同 id 时用户目录优先：

```
app/skills/{id}/            # 内置（只读，随产品发布，保证空库可初始化）
vault/.codex/skills/{id}/   # 用户自定义，可覆盖同名内置
├─ SKILL.md      # 元数据 + 何时用 / 输入 / 任务指令 / 输出结构 / 边界
├─ prompt.md     # 可选：独立的可渲染指令，占位符 {{param}}
├─ template.md   # 可选：输出骨架（保证结构稳定）
└─ sample.md     # 可选：一个正例（few-shot）
```

`SKILL.md` 的 frontmatter 必填 `name` / `stage` / `version` / `inputs`，可选 `subtitle` / `optional` / `outputs`；正文必含 `## 适用场景`、`## 输入`、`## 任务指令`、`## 输出结构`、`## 边界与注意事项` 五段。缺段视为不合格 Skill。

`kind` 决定执行方式：

| kind | 含义 | 执行方式 | 典型例子 |
|------|------|----------|----------|
| `action`（默认以外的显式声明） | 确定性业务动作 | 服务端绑定执行体（`action: topic.create`），直接写 Markdown | 新建选题、推进状态、记一笔 |
| `ai` | 需要模型处理 | 只渲染 prompt，交给外部 Agent，产物落 `01-收件箱/_ai-output/` | 选题评估、思路梳理、收支复盘 |

所有页面入口统一调用 `POST /api/skills/:id/run`，不存在绕过 Skill 的直连业务接口。

### 6.4 上下文装配

不做向量检索，用**文件路径 + 双链**做上下文，简单可靠：

1. 显式指定：调用时传 `--context "[[选题-xxx]]"`。
2. 自动扩展：读取目标笔记的 `refs`/`assets`/`topic` 字段，展开一层。
3. 知识库补充：按关键词在 `02-知识库/` 用 Obsidian 搜索取前 5 篇。
4. 预算：单次输入 ≤ 6 篇笔记、≤ 12000 字，超出按相关度截断。
5. 常驻上下文：创作六步共用同一份稿件，每次只追加本步要求，不重复贴前文。

### 6.5 输出与校验

```

          → 页面显示"待确认"卡片（DVJS 扫描 _ai-output）
          → 人工确认 → 移动到正式目录 → 建立双链
```

失败处理：解析失败重试 1 次（附错误详情），仍失败则保留原始文本并标记 `needs-review`。

### 7.1 首页

- **来源**：`09-计划/任务`、`07-稿件`、`01-收件箱`、`08-作品`+`指标`、`02-知识库`
- **视图**：时钟卡（问候+时间+日期）、日历卡（本月热力或周日历）、今日待办、当前稿件（3 条）、随手记录输入框、待处理资料计数、本月经营结果（已发布/本月成交）、作品封面墙、历史作品
- **交互**：
  - 随手记录 → 写入 `01-收件箱/`（Templater 或 QuickAdd），两个动作：`记灵感`、`放入待处理`
  - 当前稿件 → 点击跳转对应笔记
  - `编辑布局`：M6 实现，把卡片顺序与显隐存 `_配置.md` 的 `layout` 字段，DVJS 读取渲染；M0-M5 固定布局
  - `刷新本页` → 强制刷新 Dataview
- **AI**：无直接调用；作为其他模块产物的汇总看板
- **验收**：新增一条待办/稿件后，重开 Obsidian 首页仍能看到；番茄钟计时跨页不丢

### 7.2 对标与热点

- **来源**：`03-对标/博主`、`03-对标/作品`
- **视图**：5 Tab（精选总览/对标动态/博主分析/AI 热点/Twitter 动态）；4 张计数卡（监控博主/低粉爆款/异常值/近 3 天更新）
- **筛选口径**（写入 `_配置.md`）：
  - 低粉爆款：`followers < 10000 && engagement > 0.05`
  - 异常值：`views > baseline * 2`
  - 近 3 天：`publishedAt >= today - 3d`
- **交互**：`更新动态`（M4 起接 Codex 抓取，之前为"打开录入模板"）、`恢复自动更新`（开关存 `_配置.md`）、`添加博主`（新建博主笔记）、`查看获取详情`（折叠区列出各来源成功/失败）
- **AI**：`新博主分析` —— 输入博主作品表，输出内容规律与代表作品推荐
- **验收**：手工录入 1 博主 + 3 作品后，四张卡计数正确；标 `不适合` 的理由能回看

### 7.3 选题

- **来源**：`04-选题/`、`01-收件箱`、`05-拆解`、`08-作品`
- **视图**：选题库（按 status 分列看板，DVJS 分组渲染）/ 找新选题
- **三个入口**：从内部素材、从评论、从对标爆文
- **交互**：新建选题（模板）、拖拽改状态（M3 前用下拉）、`提取文案与拆解`（批量链接 → 暂存 → 转拆解）
- **AI**：`评论区选题洞察`、`内部素材选题`、`选题评估`
- **校验**：`problem`/`material` 为空时，状态选择器禁用 `selected`
- **验收**：新建选题后能在看板对应列出现；进入创作后状态自动变 `in-production`

### 7.4 拆解与沉淀

- **来源**：`05-拆解/`、`06-资产/`
- **视图**：
  - 开始拆解：三步横条（1 放入素材 / 2 核对原文 / 3 拆解结果），按 `stage` 高亮当前步
  - 可用资产：4 库统计 + 库切换 + 明细表 + `打开完整表格`
- **素材来源**：粘贴文案 / 从视频提取（粘贴链接，M4 起接转写服务，未配置时提示手工粘贴）
- **交互**：放入素材 → 生成 `05-拆解/` 笔记（stage=intake）→ 核对编辑正文 → 触发拆解 Skill → stage=result → 勾选入库生成资产
- **校验**：入库资产必须填 `problem` 与 `why`
- **验收**：一篇拆解能产出 ≥ 1 条资产；资产页能看到来源链接

### 7.5 创作

- **来源**：`07-稿件/`、`04-选题`、`06-资产`
- **视图**：6 步 Tab（聊思路/写文案/起标题/做封面/发布检查/发布）+ 顶部"选择一篇文案 + 带入文案" + 右上"常用助手"
- **交互**：
  - 步骤切换只改 `step` 字段，不改变正文
  - 选中一篇稿件后，六步共享同一上下文（不重复交代背景）
  - 做封面下挂两个封面 Skill 卡片
  - 发布 → 复制到 `08-作品/作品/` 并填发布信息
  - 录制卡片 → 生成画板入口
- **校验**：`audience` 必填，否则提示"先确认这篇要解决谁的什么问题"
- **验收**：从选题到成稿六步走完，`version` 递增，历史快照可回看

### 7.6 发布与经营

- **来源**：`08-作品/作品`、`08-作品/指标`、`09-计划`
- **视图**：月份选择器 + 4 Tab（经营总览/作品画册/内容复盘/导入数据）
- **经营总览**：本月已发布（按 `publishDate` 落在本月的作品数）、本月成交（按 `metric.deals` **记录数**，口径写在卡片上）、近 6 个月发布趋势
- **数据质量**：`qualityWarning` 列出"3 条指标缺少日期，未计入具体月份"，可点击定位
- **导入**：CSV 放到 `01-收件箱/`，运行 Node 脚本转成 metric 笔记，输出导入报告（成功数/缺失字段/冲突）
- **AI**：`周期复盘`，输出必须引用具体作品与指标
- **验收**：跨平台只记一条作品但能存多条 urls；成交数不会因播放量变化而变

### 7.7 计划

- **来源**：`09-计划/任务`、`09-计划/周`、`09-计划/月`
- **视图**：本周 / 本月；左栏今日安排 + 待安排/未完成（含优先级、原计划日期、改期）；右栏周日历
- **交互**：快速添加（输入框 → 新建任务笔记）、改期（改 `date` 并写 `originDate`）、勾选完成（改 `status`）
- **AI**：目标拆解 → 输出 `source: ai` 的任务到暂存区，人工确认后才改 `manual`
- **验收**：AI 生成的建议不会自动出现在"今日安排"；改期后仍能看到原计划日期

### 7.8 常用助手

- **来源**：`.codex/skills/`（Skill 元数据）+ `_配置.md`（收藏状态）
- **视图**：我的常用 / 全部助手，按阶段分组（整理输入/寻找选题/写作改稿/包装发布/复盘/知识库）
- **卡片**：Skill 名 + 副标题 + 收藏角标
- **交互**：点击 → 弹出运行面板（必填"本次资料"和"具体要求"）→ 生成指令或直接执行
- **校验**：两个字段任一为空，运行按钮禁用
- **验收**：新加一个 Skill 目录后，助手页自动出现该卡片（元数据从 `SKILL.md` 读取）

### 7.9 画板

- **来源**：`11-画板/*.excalidraw.md`
- **视图**：新建区 + 历史缩略图墙 + 搜索
- **交互**：新建（Excalidraw 插件）、点击打开、删除（移到 `vault/.trash`，不真删）
- **验收**：画板可从创作页的"录制卡片"跳入并回链到稿件

### 7.10 收支

- **来源**：`10-收支/`
- **视图**：月度汇总、分类占比、明细表；与本月成交并排但标注"成交为记录数，收入为金额，两者不互相推算"
- **交互**：记一笔（模板）、按 kind/date 筛选、导出 CSV
- **验收**：明细合计等于月度汇总；关联作品后能在作品页看到收入

## 八、数据来源与采集矩阵

原文只承诺"外部数据与转写服务需要使用自己的账号和配置"，没有规定怎么接。这一章把每个字段的来源、方式、频率、降级路径定死。

**核心判断：任何模块的最低可用路径不得高于 L1（平台后台导出 CSV），否则不算落地。** 抓取只能作为增强，不能作为交付承诺。

### 8.1 五个采集等级

| 等级 | 方式 | 稳定性 | 成本 | 前置条件 |
|------|------|--------|------|----------|
| L0 | 手动录入 | 总是可用 | 人力 | 无 |
| L1 | 平台后台导出 CSV | 稳定 | 免费 | 平台账号 |
| L2 | 官方 API | 配额内稳定 | 免费或低 | 账号 + 密钥 |
| L3 | Agent 抓公开页面 | 不稳定，易失效 | 低 | 遵守 robots 与频率 |
| L4 | 第三方数据平台 | 较稳定 | 付费 | 平台条款约束 |

交付时每个功能必须标明其等级，并在 UI 上可见。

### 8.2 数据源总表

| 数据对象 | 关键字段 | 首选来源 | 备选 | 等级 | 频率 | 写入位置 |
|----------|----------|----------|------|------|------|----------|
| 博主档案 | platform、followers、baseline | 手动录入主页数据 | 截图读数 | L0 | 新增时 | `03-对标/博主/` |
| 对标作品指标 | views/likes/comments/shares | 逐条复制 | 后台 CSV + 脚本对齐 | L0→L1 | 每周 | `03-对标/作品/` |
| 爆款识别 | 低粉爆款、异常值 | 由指标派生计算 | — | 派生 | 每次刷新 | 视图层现算，不落盘 |
| 对标正文 | 全文 | 复制粘贴 | 平台字幕 / ASR | L0/L1 | 每篇 | `03-对标/作品/` 正文段 |
| 自有作品 | 标题、日期、URL、封面 | 发布当日登记 | — | L0 | 发布时 | `08-作品/作品/` |
| 经营指标 | views/inquiries/deals | 平台后台导出 CSV | 手工补录 | L1 | 每周或每月 | `08-作品/指标/` |
| 成交 | deals | 收款记录逐笔登记 | 支付账单 CSV | L0/L1 | 发生时 | 指标 + `10-收支/` |
| 评论线索 | 评论文本 | 手动复制 10-20 条 | 剪贴板整理脚本 | L0 | 按需 | `01-收件箱/` |
| AI 热点 | 标题、链接、来源、时间 | RSS 订阅 | 手动 | L3 | 每日 | `03-对标/热点/` |
| Twitter 动态 | 推文文本、链接 | 官方 API | 手动 | L2 | 每日 | `03-对标/热点/` |
| 收支流水 | 金额、分类、日期 | 手工记账 | 支付账单 CSV | L0/L1 | 每周 | `10-收支/` |
| 素材正文 | 全文 | 粘贴 | 视频转写 / 飞书链接 / 本地文件 | L0/L1 | 按需 | `04-选题` 或 `05-拆解` |
| 知识库素材 | 笔记正文 | 手动写入 | 浏览器剪藏扩展 | L0 | 随时 | `02-知识库/` |
| 专注时长 | 分钟数 | 番茄钟组件写入 | — | 本地 | 每次计时 | `09-计划/专注日志.md` |

### 8.3 分平台采集路径

| 平台 | 对标公开数据 | 自有经营数据 | 正文/字幕 | 说明 |
|------|--------------|--------------|-----------|------|
| YouTube | Data API v3（配额内免费，可批量） | Studio → 分析 → 高级模式 → 导出 CSV | 字幕 API | 最规范，作为自动化示范平台 |
| B站 | 视频页手动；`api.bilibili.com/x/web-interface/view` 可取单条 | 创作中心 → 数据中心 → 导出 | 平台字幕 / ASR | 接口非官方承诺，仅作增强 |
| 公众号 | 手动 | 后台 → 内容分析 → 导出 | 正文直接复制 | 纯文本最干净，无需转写 |
| 小红书 | 无开放接口，手动 | 专业号后台可导出 | ASR | 反爬强，不承诺抓取 |
| 抖音 | 无开放接口，手动或付费工具 | 创作者中心导出 | ASR | 同上 |
| 视频号 | 手动 | 手动 | ASR | 无开放接口 |

结论：**手动 + 后台导出覆盖全部平台**；API 只在 YouTube 与 B站做增强；小红书、抖音、视频号不投入抓取工程。

### 8.4 转写与素材提取

| 路径 | 实现 | 适用 | 取舍 |
|------|------|------|------|
| 平台字幕 | B站/YouTube 自带字幕直接取 | 有字幕的视频 | 免费，质量参差 |
| 本地 Whisper | 本地模型转写 | 无字幕、注重隐私 | 免费离线，速度慢 |
| 第三方 ASR | 云端接口（自备账号） | 批量、追求速度 | 按量计费 |
| 飞书链接 | 导出 Markdown 或复制正文 | 飞书文档 | 不做授权内抓取 |
| 本地文件 | 直接读取路径 | 已有 md/txt | 最稳 |

统一入口：拆解页「放入素材」一次提交多条，全部先落 `01-收件箱/_import/`，人工核对后再推进到 `stage=verify`。

### 8.5 采集产物的写入契约

1. 所有 L1-L4 产物先写 `01-收件箱/_import/{yyyyMMdd-HHmm}/`，**不得直接进正式目录**。
2. 每条数据必须带四个溯源字段：`source`（采集等级）、`platform`、`fetchedAt`（采集时间）、`rawRef`（原始文件或链接）。
3. 每次采集生成一份 `_报告.md`：成功 n 条 / 字段缺失 n 条 / 冲突 n 条 / 跳过 n 条，并列出原因。
4. 人工确认后由脚本移动到正式目录并补 `[[wikilink]]`，移动动作留一行日志。
5. 同一条数据重复采集时，按 `platform + 原始 ID` 去重，保留最新 `fetchedAt`，旧值记入正文的「历史值」段而不是覆盖。

### 8.6 触发时机

| 时机 | 动作 | 默认状态 |
|------|------|----------|
| 每周固定 | 导出平台 CSV → 丢进收件箱 → 跑导入脚本 | 手动触发 |
| 每日 | RSS 热点拉取 | 关闭 |
| 每次发布后 | 登记作品 + 建指标笔记（空值） | 手动 |
| 每次打开页面 | 只读本地文档，不发起任何网络请求 | 强制 |

### 8.7 合规与失败处理

- 只采集公开可见数据，不登录他人账号、不绕过验证码、不突破频率限制。
- 不存储他人隐私信息，作品正文仅作研究用途并保留来源链接。
- 数据源失效时自动降级到 L1/L0，页面显式提示"数据源不可用，已降级为手工录入"，不出现空白或报错。
- 第三方平台条款变化或接口下线时，只需关闭对应采集器，不影响其余模块。

## 十一、工程约束与交付原则

### 11.1 硬约束（违反即返工）

| 编号 | 约束 | 原因 |
|------|------|------|
| C1 | 视图笔记不写入业务数据 | 保证数据唯一来源 |
| C2 | 所有关联用 wikilink，不用自造 id | 改标题不破链 |
| C3 | frontmatter 键为英文小写，值为中文 | Dataview 属性稳定 |
| C4 | 所有查询必须 `FROM` 限定目录并带 `LIMIT` | 性能 |
| C5 | AI 产物先入 `_ai-output` 暂存区 | 人在环上 |
| C6 | 删除一律进 `.trash` | 可恢复 |
| C7 | 新增字段必须同步模板 + AGENTS.md + 相关查询 | 契约一致 |
| C8 | 统计卡必须带口径说明与更新时间 | 避免误判 |
| C9 | 单页 DVJS 不超过 3 段 | 可维护 |
| C10 | 不引入需要联网才能渲染的视图 | 离线可用 |

### 11.2 交付原则（原文四条 + 三条工程补充）

1. 只解决一个最重复的任务，页面数量不增加。
2. 先定输入输出契约，再写视图。
3. 三层分离：资产层存结果、Skill 层存步骤、视图层只做入口。
4. 每条链路做四段验收：读对、传对、存对、重开能找到。
5. **可降级**：任何外部服务缺失时，功能退化为手工录入而不是报错。
6. **可迁移**：数据全为 Markdown，换工具不迁移。
7. **可解释**：AI 结论必须能指回原文或数据行。

### 11.3 变更管理

- 字段变更：先在 `_配置.md` 记录变更（旧值 → 新值 → 影响范围），再批量改模板与笔记。
- Skill 变更：`SKILL.md` 内写版本号；输出结构变更需同时更新 `template.md`。
- 破坏性变更：保留一个里程碑的兼容期（查询同时兼容新旧字段）。

## 十二、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| Dataview 大库性能下降 | 首页卡顿 | 目录限定 + LIMIT + 预计算缓存笔记；超 5000 篇评估 Bases |
| DVJS 过度使用 | 难以维护、易白屏 | 单页 ≤ 3 段，统一走组件函数，全部 try/catch |
| AI 输出结构漂移 | 落盘后查询失效 | `template.md` 固定骨架 + 入库校验 + 重试 |
| 字段随意新增 | 查询与模板漂移 | C7 约束 + 变更记录 |
| 数据源不可得 | 对标模块空转 | 手工录入优先，抓取作为增强；空态给出录入入口 |
| 口径混用 | 复盘结论错误 | 三口径字段隔离 + 卡片标注 + 导入校验 |
| Skill 与产物脱节 | 助手页与实际情况不符 | Skill 元数据从 `SKILL.md` 读取，单一来源 |
| 用户不会用 | 交付失败 | 免费版只留四块；每页顶部一句话说明；配套教程 |

## 十三、附录：演进到自研 Web 的触发条件

仅当满足以下任两条时，才启动 M7：

1. vault 笔记数 > 5000，Dataview 首屏 > 3 秒。
2. 需要多人协作或移动端深度编辑。
3. 需要复杂交互（拖拽看板、实时协同编辑、富媒体预览）。
4. 需要对外售卖 SaaS 形态。

迁移路径：Markdown 仍是真相源，Web 层只做只读镜像 + 写操作走 API 回写文件；不引入第二套数据模型。
